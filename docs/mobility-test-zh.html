Mobility：冻结模型后的独立测试评估

本步骤使用已保存的 MobilityLSTM-v1、原训练集拟合的归一化参数，以及原始测试窗口。它不训练、不选模型、不调整参数，也不启动 UI 或改变模拟器的连接策略。

评估规则

项目固定设置
模型训练结果目录中的 best.keras；必须是完整正式训练，不能是 smoke。
输入与输出8 个历史点 × 6 个特征，预测 60 秒后的二维位移，再转换为经纬度。
预处理读取 preprocessing.json；仅应用，不重新拟合。顺序、单位和投影必须与训练一致。
测试数据poly_01 / poly_02 × 2.0、4.1、6.0 m/s，共 6 次运行、672 个窗口。包括未连接节点的窗口。
对照HoldPosition、ConstantVelocity、LSTM 使用完全相同的窗口与真实目标。
主指标位置 RMSE：先按地球半径 6,378,137 m 计算每条预测的大圆距离误差，再求平方均值的平方根。
辅助指标平均距离误差、中位数、P90。按案例和配置速度报告，不挑选有利子集。
隔离先校验训练文件和窗口清单，再写入 frozen-protocol.json，之后读取 test.jsonl。不会读取 train.jsonl 或 validation.jsonl。

运行顺序

先安装，再在项目根目录、dissect-fog 环境中运行：

python predictor-ui/scripts/mobility/test_mobility_evaluation.py
python predictor-ui/scripts/mobility/evaluate_mobility_test.py --training "本次训练结果目录" --windows "该次训练使用的原始窗口目录"

预期：8 个单元测试通过，随后出现 MOBILITY_TEST_EVALUATION_OK。默认结果写入 simulator/sim_res/mobility-evaluation/时间戳-唯一编号/，终端显示 evaluation.json 的完整路径。每次使用新目录，已有结果不会覆盖。

输出文件

文件用途
frozen-protocol.json读取测试数据前记录模型、归一化文件、数据身份和指标；状态固定为 FROZEN。
evaluation.json本次评估状态、原始文件校验信息与输出文件 SHA-256。完成后为 COMPLETE。
test_metrics.json三种方法的整体误差。
test_by_case.csv / test_by_speed.csv各案例与各速度的误差。
test_predictions.csv2,016 条记录：三种方法 × 672 窗口，含预测/真实经纬度、时间、位置误差。
source-training.json / source-windows.json / source/来源清单与本次评估脚本快照，便于复核。

结果如何解释

测试成绩是这次冻结方案的独立评估，不是上线批准。不设一个测试阈值再自动选择模型；也不根据测试成绩反复改网络、挑 epoch 或拟合 scaler。若之后继续探索模型，本次测试集已被查看，后续正式结论需要新的独立评估设计。

672 个窗口相互重叠，只来自两条保留路线，不等于 672 条独立轨迹。本步骤只评估位置误差；覆盖范围告警、连接切换效果以及实时影子预测尚未评估。各速度均曾出现在训练中，主要考察未见路线的表现。
