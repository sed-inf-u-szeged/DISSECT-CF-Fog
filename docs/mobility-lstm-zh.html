Mobility LSTM v1：离线训练与验证

本步骤从已完成的窗口训练第一个移动位置预测模型。使用 TensorFlow/Keras，从新初始化的权重开始；不加载负载预测任务的旧权重。仍未接入模拟器在线推理、影子接管或主动切换。

输入与模型

项目固定配置
输入8 个历史点 × 6 个特征：相对东/北位置、观测速度、方向 sin/cos、方向有效标记。
目标60 秒后的东/北位移（2 个输出），可还原为经纬度。
结构LSTM(32) → Dense(16, ReLU) → Dense(2, linear)，5,554 个参数。
训练Adam，学习率 0.001，clipnorm=1，batch=64，最多 60 轮，seed=42。
停止与选模验证集缩放后 MSE 越低越好；连续8轮没有严格改善即停止；保存验证损失最低轮。没有达到质量门槛即自动接管的逻辑。
运行CPU，最多2个算子内线程。训练批次间检查600秒时间限制，超时标记失败并保留已有文件。TensorFlow初始化及单次底层操作不保证被该限制立即中断。

数据隔离与标准化

训练：2,688 个窗口；验证：672 个窗口。脚本只读取 train.jsonl 和 validation.jsonl，不读取 test.jsonl，甚至不计算测试文件哈希。读取 windows.json 中已有测试数量等元数据不等于评估测试集。

X 的前三列只使用训练窗口所有历史槽位拟合均值和标准差；重叠窗口会重复计入，这是本版明确的权重口径。方向 sin/cos 与有效标记不标准化。Y 使用训练目标全部坐标分量的均方根作为同一个尺度，除以该尺度且不中心化；两个方向保持相同损失权重。零方差输入使用尺度1，目标尺度最小为1米。

验证集沿用训练得到的参数，参与选模和早停，不参与梯度更新或标准化拟合。测试集留到模型方案确定后的独立评估。禁止把目标位置、路线ID或其他元数据拼入模型输入。

公平比较与指标

HoldPosition 预测位移为0；ConstantVelocity 延续最后两个观测点之间的位移。在固定线性投影下，它与 Java 的 2×当前位置−上一位置 经纬度外推一致。这两种方法与 LSTM 使用相同的672个验证窗口，包含断连时刻。

每个预测位置先还原为经纬度，再用地球半径6,378,137米的球面距离计算误差。输出平均、中央値、P90、RMSE，以及逐场景结果。不是负载任务的±20%准确率。本步暂不计算离开节点覆盖的分类指标。

选模依据是投影位移的验证 MSE，最终位置指标使用球面距离。均值与RMSE可能给出不同排序，应共同报告；不能只挑更好的一项。验证路线仅两条，窗口高度重叠，这仍是先导实验，不能据此宣称真实场景泛化性能。

输出文件

文件用途
best.keras最佳轮模型结构、权重及优化器状态；只保存标准Keras层。
preprocessing.json训练集标准化参数、输入列顺序、目标尺度和投影。预测时必须和模型配套使用。
history.csv逐轮训练/验证损失及验证平面RMSE。
validation_metrics.json三种方法在同一验证集上的位置误差汇总。
validation_by_case.csv按场景细分位置指标。
validation_predictions.csv逐窗口预测和真实经纬度、误差。
training.json运行状态、参数、版本、来源和输出哈希、最佳轮、重载检查。
source-windows.json / source / model-summary.txt来源清单、构建/训练脚本快照与模型结构。

每次运行在 sim_res/mobility-training 创建唯一目录，原始采样和窗口保持不变。仅 status=COMPLETE 且 reload_check=PASSED 的结果用于下一步。smoke模式只运行2轮，不能与完整训练混淆；正式命令不使用 --smoke。

已验证与仍待确认

本地 Linux 独立环境使用 Python 3.12、TensorFlow CPU 2.21.0、Keras 3.15.1 完成真实训练、最佳模型加载及配套预处理重载检查。与用户 Windows 的 NumPy 补丁版本不同，操作系统也不同；不承诺逐位相同结果，不要求用户升级依赖。

纯数据回归检查覆盖训练集专用标准化、无原地修改、固定参数应用到验证分布、零方差、基线方向和尺度、球面误差单位、失败清单拒绝。实际训练在没有 test.jsonl 的目录完成；840个对应的验证基线预测位置与Java导出完全一致。本地观察为LSTM的RMSE较低但平均误差略高于恒速，未因此调整本版超参数。Windows安装与运行结果待确认。
