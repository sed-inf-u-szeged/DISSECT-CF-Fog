本次入口做什么

  1. 校验已安装的数据集清单。
  2. 为本批创建全新目录，保存完整配置、六个相关 Java 源文件和实际编译运行所用 classes / JAR 的快照与哈希。Git 提交号与未提交状态同时记录。
  3. 在快照内编译六个相关 Java 文件，项目工作区源码和 target/classes 不被改写。
  4. 每个场景启动独立 Java 进程，关闭 UI，保留独立日志和结果目录。
  5. 检查 121 条观测、时间间隔、原始坐标对应关系、派生运动字段、预测时间配对及最终数据守恒。
  6. 每完成一个场景更新 batch.json。失败或中断即停止，其余保留 PENDING，不自动重试、不覆盖旧批次。

逐步运行

在项目根目录的 PowerShell 中，激活原环境后执行本轮试跑：

conda activate dissect-fog
python predictor-ui/scripts/mobility/run_mobility_batch.py --smoke

成功应看到 cases=3 passed=3 sample_rows=363 training=NOT_STARTED 和 MOBILITY_BATCH_OK。只在确认试跑之后，下一步才使用同一入口的 --all。每次命令都会创建新批次；本次试跑不合并进以后完整批次，避免重复计数。

边界与解释

  • 每个场景 121 条观测；最终结算不是新位置样本。363 条观测不是 363 条独立轨迹，也不是训练窗口数。
  • 默认超时为每个场景 120 秒墙钟时间，与模拟的 120 分钟不同。超时保留日志并失败退出。
  • 速度是相邻观测的端点位移 / 时间，方向是前一点指向当前点的初始方位角。第一行无运动历史，相关字段留空。
  • 停留在覆盖范围外的观测也保留；NONE 表示未连接，不应直接从位置预测数据中删除。
  • 模型基线仍为 HoldPosition 与 ConstantVelocity，不需要训练。当前采集校验不等于学习模型的性能验收。
  • 批量校验覆盖采集完整性与主要一致性；窗口构建时还需独立检查标签时刻、训练泄漏和预处理。
  • 36 场景是先跑通 workflow 的小规模试点；固定种子、重复路线和少量路线组限制泛化结论。训练前不依据测试集预测结果调整路线。
  • 多节点、多设备、更多运动策略、可变速度、噪声和真实轨迹属于后续扩展，本轮基础设施仍为两个节点、一台设备。
