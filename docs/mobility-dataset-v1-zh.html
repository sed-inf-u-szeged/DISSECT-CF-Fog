文件与身份

dataset-plan.json 固定 route_id、case_id、split、速度、seed 和配置校验值。36 份 properties 分别存放在 train、validation、test 下。case_id 如 rect_01_s20 表示 rect_01 路线、2.0 m/s。

case_id 表示计划实验，run_id 表示某一次实际运行。重跑同一 case 会产生新的 run_id，不能算成新的路线。未来批量运行工具需记录两者对应关系、状态、结果目录、源码版本及配置校验值；本次还未实现批量工具。

输入、标签与隔离

  • 先按清单划分，再在每个独立 run/device 内构造窗口。最近 8 个点相隔 60 秒，首尾相距 7 分钟；目标是最后输入点之后 60 秒的位置。
  • 只从历史观测构造位置、速度、航向。计划路线、目标位置及未来节点不能进入输入。速度是相邻端点位移/时间，航向是上一点到当前点的方位角。
  • 同一路线的所有速度、种子、重复运行和重复圈只能属于同一集合。重复几何形状（包括反向起点变化）不能伪装成新路线；检查器也拒绝平移、旋转、镜像或缩放等价形状跨集合。
  • 矩形/三角形与折线/不规则多边形分属不同集合，这是路线类型留出试验。验证和测试路线组较少，不能据此作广泛的泛化结论；后续需要增加独立路线。
  • 原来三个已查看的开发示例不纳入本批清单。测试集仅可做机械有效性及数据完整性检查，不按预测表现挑选、删除路线或调参。
  • 断连记录保留用于位置预测。没有原连接节点时，覆盖判断不适用；当前模拟器的基线覆盖预测仍仅在已连接时产生。完整学习模型位置评估尚待实现。

检查结果和限制

助手环境已验证：12 条闭合且无自交的路线，36 份配置，24/6/6 划分；所有配置经现有 Java MobilityScenarioConfig 读取并构造路径成功；未执行这 36 次仿真。只读检查器通过正常案例及 CRLF 兼容检查，并拒绝 7 类异常输入。

静态配置有效不等于仿真一定能完成。后续要检查每次运行是否成功排空数据、采样是否连续和预测目标是否匹配。失败运行必须登记原因，不得静默丢弃。若修改路线或划分，生成新的计划版本，不能根据测试集预测好坏修改路线。
