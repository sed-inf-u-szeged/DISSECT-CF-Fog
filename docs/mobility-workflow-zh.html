现在到底有哪些真实数据？

实际路径来自模拟器：设备按照配置的航点和移动策略运动，采样器记录当前位置。这里的“实际”是仿真实际观测，不是现实 GPS 数据，也不是 LSTM 生成的路径。一个设备、两个雾节点是当前实验配置，不代表模拟器能力只能如此。

字段含义
run_id / device_id / time_ms运行、设备身份和模拟时间（毫秒）
latitude_deg / longitude_deg纬度、经度（度）
delta_time_s / displacement_m距上一观测的时间与两端点间距离
observed_speed_m_s端点位移除以经过时间；不是瞬时速度，转弯时可低于设定速度
heading_deg从上一位置指向当前位置的初始方位角，范围 [0,360)
motion_valid / heading_valid运动/方向有效标志；首个观测没有上一时刻，近乎静止时方向无效
current_node当前连接节点，也记录断连

采样间隔 60 秒，每次运行 121 条观测。早期 UI 的 122 帧包含最后结算帧，不是 122 次训练或独立模拟。先前只有 HoldPosition 和 ConstantVelocity 规则基线；现在已经另外完成真正的 LSTM 训练。

模型如何预测？

使用 8 个历史点，每点 6 个特征：相对当前点的东/北位移、观测速度、方向角正弦/余弦、方向有效标志。输出是 60 秒后的东/北位移，再转换回经纬度。首条观测没有速度，因此第一个有效输入需要累积 9 条原始观测。有效断连、静止样本保留；节点身份不作为输入。

LSTM(32) → Dense(16) → Dense(2)，共 5,554 个参数。预处理只用训练集拟合；验证集选择最佳检查点。测试和影子推理都使用已经保存的模型及预处理，不重新训练。这个模型针对 mobility 训练，并非直接使用负载预测模型的权重。

模拟器中的时间顺序

  1. Java 产生当前时刻观测并交给常驻 Python worker。
  2. 若旧预测的目标时间等于当前时间，先用刚到达的真实位置评价它。
  3. 历史窗口有效且允许下一目标时，冻结模型与两个基线发出新预测。
  4. 保存预测并回复 Java，然后模拟器继续前进。
  5. 最后一个观测只结算到期预测，不再发出预测；检查待评价数量为零。

“同一模拟时刻回复”表示模拟器等待 Python，模拟时间尚未推进；不表示推理没有现实耗时，也没有模拟网络时延。预测不会触发提前切换，连接仍使用现有被动响应策略。

结果与准确性边界

下表为独立测试集的位置大圆距离误差，单位米，越低越好。

方法平均误差RMSEP90
HoldPosition235.421253.875360.001
ConstantVelocity61.507118.703226.492
LSTM80.813101.419162.836

LSTM 的整体 RMSE、P90 优于匀速基线，但平均误差更差，不是全面胜出。当前数据规模小、路线为合成重复轨迹，不能据此宣称现实场景普遍有效。

开发用三角路线影子会话完成 112 个预测起点、336 条评价、345 条顺序事件、0 个未结算预测。三种方法的 RMSE 分别为 236.979、131.435、97.825 米。它是集成验证，不是另一份独立测试。

Windows 会话内特征一致性 EXACT 通过。Windows/Linux 分别重算的方向正余弦存在最多约 1.11×10−16 浮点差异，因此不承诺跨平台逐位相同。
